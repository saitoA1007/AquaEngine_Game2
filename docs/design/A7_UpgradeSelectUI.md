# A7-1 強化の選択画面の見た目

確定日: 2026-11-10。人間の言葉は「設計はそれで構いません」と「クラスごと分けてくれたほうがレビューしやすいので、分けてください。それで設計を確定してください。」。最初の依頼は「強化選択UI、PhaseUI、氷の範囲、HITUIに関してもテクスチャかエンジン機能を使ってさらにかっこいいものにしていきたいです」。

強化選択画面の動作(カーソル、決定、結果の通知)は[ProgressionDesign.md](ProgressionDesign.md)の「7. 強化」。ここは見た目と開くときの動きだけを決める。

## 見た目

- カードは角を斜めに切った形。中の板と2重線の枠の2枚の画像を重ねる。画像は白で作り、色はコードで掛ける(`DebugParameter`)。
    - 選んでいないカード: 暗い半透明の板と、少し暗い白の枠。
    - 選択中のカード: 枠を青(HPアイコンの核の色と同じ)にして1.08倍に大きくする。さらに枠の上を光の粒が一周する。
- 流れる光: 光の位置を変えたコマ(32コマ)を1枚の画像に8列x4行で並べ、`Sprite::SetUvMatrix`(UVの拡大縮小と移動)でコマを切り替える。コマの間には余白(10px)を取る。カーソルが動いたら、移った先のカードで最初から回る。
- 見出しの下に、ひし形のついた区切り線の画像を置く。
- 文字(見出し、名前、説明、取得回数、案内)に影を付ける。同じ文字を暗い色で少しずらして先に描く。
- 入れないもの: 種類ごとのアイコン、取得回数の印、背景の変更。背景の暗い板は黒の半透明のまま。

## 開くときの動き(破片が集まってカードが組み上がる)

- 破片は、カードを傾けた格子で割ったもの(下の「破片の作り方」)。板と枠の破片は同じ割れ方で、重ねて動く。
- 破片は、カードのまわりに散らばって傾き、透明な状態から始まる。元の位置へ集まりながら、回転を戻して見えるようになる。カードは左から順に少しずつ遅れて始める。
- 組み上がったら、1枚のカードの画像へ切り替える。その後、カードの文字がふわっと出て、選択中の表示と流れる光が始まる。
- 長さは仮に0.6秒(最後のカードが組み上がるまでの全体の長さ)。組み上がるまで、決定もカーソル移動も受け付けない。従来の`confirmLockTime`(0.4秒)は、この長さに置き換えた。Aを一度離すまで決定しない処理は残す。
- 見出しと案内は、開いた時点からそのまま出す。閉じるときの動きはない。
- 散らばる距離、回転の大きさ、遅れ、長さ、文字が出る時間、破片の割り方、各色は、`DebugParameter`(`UpgradeSelectUI`の`Motion`、`Shard`、`Color`)で調整できる。初期値は仮。
- 動きは止まらない時間(`FpsCounter::GetDeltaTime`)で進める。

## エンジンの制約(ソースで確認済み)

- 2Dの合成は通常のアルファだけ。`SubmitSprite`では加算を選べない。
- `Text`は単色の塗りだけ。
- 2DはUI専用のパスに描かれ、ポストエフェクトはかからない。
- 同じパスの2Dは、PSOごとにまとめて描かれる。実際はスプライトの上に文字が出ているが、順番は保証されていない。
- `Sprite`の`textureLeftTop_`は、コンストラクタでしか使われない。コマの切り替えは`SetUvMatrix`で行う。

## 破片の作り方(傾けた格子)

2026-11-10に、画像の表で割る方式から、実行時に傾けた格子で割る方式へ変えた。人間の言葉は「このkEntriesがごり押しすぎて理解できるコードになってない」「人間が破片の割れる位置を理解しているのがおかしい」。「UVをうまくつかって四角っぽく見せない方法はない?」と聞かれて、「傾けた格子で」に決まった。

- 破片用の画像は作らない。カードの板と枠の画像(`UpgradeCardPlate.png`、`UpgradeCardFrame.png`)をそのまま使う。
- カードを、`shardAngle`度傾けた`shardColumns`×`shardRows`の格子で割る。仮の値は30度、3×4。
- 格子の線の間隔は、シードを固定した乱数で、最大`shardJitter`(間隔に対する割合。仮の値は0.3、上限0.45)だけずらす。行の線は全体でそろえ、列の線は行ごとにずらす(ずらしても、行の中で隙間なく並ぶ)。
- 格子は、傾けたカード全体を覆う範囲だけ作る。カードの四角と重ならない区画には破片を作らない。
- 破片1枚は、傾いた四角のスプライト1枚(板と枠で計2枚)。`rotate_`で傾け、`SetUvMatrix`の回転も同じ角度にして、その四角に写るカードの部分を切り出す。組み上がると、破片がぴったり並んで1枚のカードと同じ見た目になる。
- 散らばる向きは、カードの中心から破片の中心へ向かう向きに、乱数で少しばらつきを足す。傾きと距離も乱数で決める。シードは固定なので、開くたびに同じ動きになる。
- 調整値(`shardAngle`、`shardColumns`、`shardRows`、`shardJitter`)を変えると、破片を割り直す。列と行は6まで(破片のスプライトを、あらかじめ6×6の36枚ぶん用意してあるため)。
- 破片は、画像の1枚ぶん(余白込み)のUVで切り出す。スプライトのサンプラーが`D3D12_TEXTURE_ADDRESS_MODE_WRAP`(`PSOManager.cpp`)なので、傾いた四角が画像の外へはみ出すと、反対側の絵が映る。これを防ぐため、画像はカードのまわりに透明な余白を取った760x760(表示の大きさ。縦横が同じなので、UVの回転でゆがまない)にした。格子の最大の半径は約340なので、余白に収まる。本体のスプライトも760x760にして、破片と同じ画像・同じ写し方にした(見た目のカードの大きさは300x380のまま)。

## 構成

| ファイル | 役割 |
| --- | --- |
| `Application/Game/Upgrade/UpgradeSelectUI.h/.cpp` | 開閉、カーソル、決定、組み上がりの待ち、調整値の登録。見出し・区切り線・暗い板 |
| `Application/Game/Upgrade/UpgradeCardView.h/.cpp` | カード1枚分。板・枠・光・破片のスプライト、文字と影、組み上がりの動き、光のコマ送り。`UpgradeSelectTextures`(画像のハンドル)、`UpgradeCardStyle`(調整値)、`ShadowedText`(影付きの文字)も定義する |

| `Resources/Textures/UI/Upgrade/` | 画像4枚(カードの板、枠、光のコマ、区切り線) |

- クラスをカード単位で分けるのは人間の判断(レビューしやすくするため)。
- 画像の元: TD2_2の`AIRecords/AssetWork/Jobs/a7f1c0de5b2a4e8f9c3d6b1e7a408d52/sources/`の`build_upgrade_card.py`(Blenderで`--background`実行)と`upgradeCard.blend`。
- 画像の寸法: 板と枠は1520x1520(表示は760x760で、300x380のカードが中央に入る)。光は1コマ320x400。区切り線は1280x64(表示は640x32)。
- 破片の継ぎ目: 破片どうしは重ねず、ぴったり並べる。飛んでいる間と組み上がる瞬間に、隙間がちらつかないかは、実際に見て確かめる。
