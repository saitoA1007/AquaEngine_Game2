# 実装・検証・コードレビュー手順

この文書は[AGENTS.md](../../../AGENTS.md)を実際の作業へ適用する手順。新たな実装権限を与えるものではなく、ルールや書式の正本はAGENTS.mdに置く。

## 1. 着手前の整理

現在の依頼と採用済み設計から、次を短く整理する。小さな作業では会話内で十分であり、毎回の文書生成は不要。

- 実現する目的と完成条件
- 確定仕様と未決定事項
- 変更するファイル・データと、今回扱わない範囲
- 段階実装の区切り、または明示された一括実装範囲
- 検証方法と、人間が評価する挙動

Gitの状態・差分を読み取り、既存変更と今回の変更を区別する。関連するAPI・使用例を確認する。ゲーム設計に関わる未決定事項は人間へ戻す。

未知の技術が必要と分かった場合は、仕組み・採用理由・代替案・注意点を説明し、人間の理解を確認してから方針を決める。既知の処理の理解確認を毎回繰り返さない。

## 2. 実装

許可された範囲で実装し、既存の登録・接続方式を使う。機能不足が疑われた場合は[調査記録](../FeatureGaps.md)の項目に沿って整理する。代替案の採用と実装を混同しない。

ゲームのコード・アセットと、それらを作るための説明文書を分ける。調整値の変更箇所と、保存済みデータの優先関係が人間に分かる状態にする。

## 3. 検証

書き込み先をAGENTS.md第4節・第11節と照合してから、変更に必要な検証だけを行う。許可済みの生成物等の更新と、既存の共有設定・保護対象への変更を区別する。Resources内でも、既存の共通シェーダーをゲーム専用素材として扱わない。

| 観点 | 具体例 |
| --- | --- |
| 技術的成立 | 対象構成でのビルド、起動、素材の読み込み |
| 仕様との一致 | 決定した操作と期待結果、対象外の挙動が増えていないか |
| 寿命・順序 | 生成・削除・シーン遷移・再開始・同時接触・参照の失効 |
| 境界・失敗 | 素材不足、空データ、上限、対象消失等のうち変更に関係するもの |
| 保存・差分 | 保存先、再読み込み、既存データへの影響、許可外変更の有無 |

すべての作業で全項目を実行するのではなく、影響に応じて選ぶ。実行できない項目は未確認として理由を報告する。人間の体験評価は技術検証と別に扱う。

## 4. コードレビュー

レビューだけの依頼では、指摘と修正案の提示に留め、実装やルール文書の変更へ自動的に進まない。

1. 採用済み仕様と差分を照合し、設計の無断変更・不要な機能追加がないか確認する。
2. 所有権、参照の寿命、更新順、衝突コールバック、共有データ変更、保存副作用を、関係する範囲で確認する。
3. 重複処理や過度な抽象化を、具体的な変更理由・影響から評価する。
4. 書式はAGENTS.md第10節を基準に確認する。書式そのものに問題を感じた場合は、具体例・影響・改善案を示す。人間が採用するまで規約を変更せず、周辺コードも一括整形しない。
5. 指摘には発生条件・根拠となる箇所・影響・修正案を添える。推測と確認済みの問題を区別し、好みだけの指摘を必須修正にしない。

報告は重大な問題から並べる。問題が見つからなかった場合も、レビュー範囲と未検証事項を示す。

## 5. 引き渡し

- 何が変わり、どう使うか
- 主な処理の流れ、採用理由、前提、注意点
- 実施した検証と結果、未確認事項
- 人間に確認してほしい操作感・見た目・仕様との一致
- 未決定事項が残る場合は、その判断点

実装完了、検証完了、人間による理解確認、体験の採用をそれぞれ区別する。ステージング・コミット・公開は別の指示に従う。
